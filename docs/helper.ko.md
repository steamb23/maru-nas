# 권한 도우미

권한 도우미(`maru-helper`)는 root로 도는 별도 서비스입니다. 대시보드 자신은 권한이 없는 전용 사용자로 돌고 권한을 올릴 수 없으므로, 다음 일은 도우미를 거칩니다.

- **사용자 권한 연산**: 로그인한 사용자 자신의 Linux 계정(uid, 기본 그룹, 보조 그룹)으로 파일을 읽고 씁니다. 실제로 열 수 있는지는 커널이 소유권과 ACL로 판단하므로 SSH로 접속할 때와 같은 권한이 적용됩니다. 대상은 그 사용자의 홈 디렉터리와 `/srv` 아래에 마운트된 데이터 디스크뿐입니다. [파일 탐색기](files.ko.md)가 이것을 쓰고, [웹 터미널](terminal.ko.md)의 일회용 SSH 키도 이 권한으로 넣고 지웁니다.
- **root 권한 연산**: 관리자가 비밀번호를 다시 입력하면 그 대시보드 세션에서 5분 동안 정해진 root 연산을 쓸 수 있습니다(sudo와 비슷합니다). 임의의 명령을 실행하는 기능은 없고, 기능마다 필요한 연산만 따로 만들어 둡니다. 지금은 실행 권한 확인, [대시보드에서 업그레이드](upgrade.ko.md#대시보드에서-업그레이드)의 업그레이드 요청, 파일 탐색기의 디스크 휴지통 만들기가 있습니다.

OMV 공유 폴더의 권한(Privileges) 설정은 SMB·FTP 같은 서비스의 것이라 도우미는 따르지 않습니다. 파일 탐색기에서 따르게 하려면 [OMV 공유 폴더 권한 따르기](files.ko.md#omv-공유-폴더-권한-따르기)를 켜고, 도우미 수준에서 막으려면 OMV에서 공유 폴더의 ACL을 바꿉니다.

설치 스크립트가 기본으로 설치합니다. 질문에서 설치하지 않기로 하거나 `--no-helper`를 주면 설치하지 않으며, 이때 도우미가 필요한 기능은 쓸 수 없지만 나머지 기능은 그대로 쓸 수 있습니다. 설치 상태와 지금 세션의 실행 권한, 권한 상승은 관리자가 설정 앱의 "서버" 페이지에서 확인합니다.

## 보안 설계

도우미는 대시보드의 말을 그대로 믿지 않습니다. 대시보드가 뚫려도 곧바로 root나 모든 사용자의 권한이 되지 않게 하기 위해서입니다.

- 소켓(`/run/maru-helper/helper.sock`, 권한 `0600`)에는 대시보드 서비스 사용자만 접속할 수 있습니다.
- 로그인할 때 대시보드가 받은 비밀번호를 도우미가 직접 확인한 뒤에만 그 세션에 티켓을 발급합니다. 티켓은 도우미 메모리에만 있으며, 로그아웃·세션 만료 때 폐기되고 도우미나 대시보드가 다시 시작하면 모두 사라집니다. 2단계 인증을 쓰는 계정은 인증을 마친 뒤에야 티켓을 쓸 수 있습니다.
- 티켓을 주는 계정은 OMV 로그인과 같은 기준입니다. root는 받지 않고, `openmediavault-admin` 그룹이거나 일반 사용자 uid 범위(`/etc/login.defs`의 `UID_MIN`~`UID_MAX`)여야 합니다.
- root 권한 상승은 `openmediavault-admin`과 상승 그룹(기본값 `sudo`, 설치할 때 `--elevate-group`으로 바꿈) 모두에 속한 사용자만, 비밀번호를 다시 입력해야 할 수 있습니다. 상승은 그 세션에만 붙고 5분 뒤 끝나며(연산을 해도 늘어나지 않습니다), 서버 페이지에서 바로 끝낼 수 있습니다. 상승 그룹을 `openmediavault-admin`으로 정하면 OMV 관리자는 모두 상승할 수 있습니다.
- 비밀번호 확인은 사용자마다 5분 안에 3번 틀리면 30초부터 두 배씩 최대 15분 동안 잠깁니다. 이 잠금으로 계정이 영구히 잠기지는 않습니다.
- 연산은 매번 자식 프로세스로 실행하며, 사용자 권한 연산은 시작하기 전에 그 사용자로 권한을 내립니다. root 프로세스는 파일 내용을 다루지 않습니다.
- systemd 유닛은 root여도 필요한 권한과 쓸 수 있는 경로만 남겨 둡니다. `systemd-analyze security maru-helper`로 점검할 수 있습니다.
- 비밀번호와 티켓은 기록하지 않습니다. 도우미는 비밀번호 확인 결과, 모든 root 연산, 파일 쓰기 연산(경로 포함)을 `journalctl -u maru-helper`에 남깁니다. 파일 읽기는 경로 없이 연산과 결과만 남깁니다.

## 남는 위험

- 대시보드가 뚫리면 공격자는 그때 로그인해 있는 사용자의 티켓을 쓸 수 있고, 그 뒤에 입력되는 비밀번호를 가로챌 수 있습니다.
- OMV 관리자는 원래 OMV 웹 UI로 root와 같은 일을 할 수 있으므로, 도우미의 root 권한 상승이 관리자에게 새로운 권한을 주지는 않습니다.
- 대시보드에서 업그레이드를 켜면 상승한 세션으로 할 수 있는 일이 넓어집니다([보안과 주의](upgrade.ko.md#보안과-주의)).

## 제한

- 계정은 로컬 `/etc/passwd`·`/etc/group`과 `/etc/shadow`로만 확인합니다. LDAP 플러그인 등으로 들어오는 계정은 대시보드에는 로그인할 수 있지만 도우미 티켓은 받지 못합니다.
- 홈 디렉터리가 `/home`이나 `/srv` 아래가 아니면 읽기만 할 수 있습니다.

## 설치 확인

```sh
systemctl status maru-helper.socket
```

로그인한 뒤 설정 앱의 "서버" 페이지에서 "실행 권한"이 내 계정의 uid로 나오는지, 권한 상승 뒤 "실행 권한(root)"이 uid 0으로 나오는지 확인합니다. 도우미가 받은 요청과 결과는 다음 명령으로 봅니다.

```sh
journalctl -u maru-helper -e
```
