# 설정

설치한 뒤의 설정은 `/etc/default/maru`의 환경 변수나 명령줄 플래그로 합니다. 값을 바꾼 뒤에는 `sudo systemctl restart maru`로 다시 시작해 주세요. 설치할 때 묻는 값은 `./install.sh --reinstall`로 바꾸는 편이 안전합니다([설정 바꾸기](install.md#설정-바꾸기)).

지금 쓰는 값과 그 출처(기본값, 환경 변수, 명령줄 플래그)는 관리자가 [설정 앱](settings-app.md)의 "서버" 페이지에서 볼 수 있습니다.

## 웹에서 바꾸는 값

워크벤치 주소(`-workbench-url`), SMART 확인 시각(`-smart-refresh-at`), 웹 터미널 허용(`-terminal`)은 설정 앱의 "서버" 페이지에서도 바꿀 수 있습니다.

- 여기서 바꾼 값은 다시 시작하지 않아도 바로 적용되고, 플래그·환경 변수보다 우선합니다(상태 디렉터리의 `site.json`에 저장).
- `install.sh`로 다시 설치하거나 업그레이드해도 그대로 남습니다. 플래그 값으로 돌아가려면 그 페이지에서 "서버 값 사용"을 눌러 주세요.

## 항목

| 플래그 | 환경 변수 | 기본값 | 설명 |
|---|---|---|---|
| `-listen` | `MARU_LISTEN` | `127.0.0.1:8090` | 수신 주소입니다. 루프백 `host:port` 또는 `unix:/절대/경로.sock`(Unix 소켓, 권한 `0660`)을 지정합니다([수신 방식 고르기](reverse-proxy.md#수신-방식-고르기)). |
| `-allow-non-loopback` | `MARU_ALLOW_NON_LOOPBACK` | `false` | 루프백이 아닌 TCP 주소(`0.0.0.0:8090` 등)도 허용합니다. 위험하니 [수신 방식 고르기](reverse-proxy.md#수신-방식-고르기)의 경고를 먼저 읽어 주세요. |
| `-omv-url` | `MARU_OMV_URL` | `http://127.0.0.1` | OMV 웹 UI(nginx) 주소입니다. 루프백 주소만 받습니다. OMV 웹 UI 포트를 바꿨다면 포트까지 적어 주세요(설치 스크립트는 nginx 설정에서 포트를 찾아 제안합니다). 평문 HTTP로만 접속하므로 OMV의 "Force SSL/TLS"는 꺼져 있어야 합니다. |
| `-cookie-path` | `MARU_COOKIE_PATH` | `/` | 브라우저가 보는 대시보드 경로(세션 쿠키의 Path)입니다. 경로 접두사 아래에 둘 때 좁힐 수 있습니다. |
| `-state-dir` | `MARU_STATE_DIR`, `STATE_DIRECTORY` | (없음) | 대시보드 상태를 저장할 디렉터리입니다. 비워 두면 메모리에만 보관하므로 재시작하면 사라집니다. 설치하면 systemd가 `STATE_DIRECTORY`로 `/var/lib/maru`를 넘겨줍니다. |
| `-smart-refresh-at` | `MARU_SMART_REFRESH_AT` | `00:00` | SMART 정보를 하루 한 번 다시 가져오는 기준 시각입니다(`HH:MM`, 서버 로컬 시간). 마지막 조회가 이 시각 이전이면 다음 접속 때 다시 가져옵니다. SMART 조회는 대기 중인 디스크를 깨우므로 자동 주기 조회는 하지 않습니다. |
| `-workbench-url` | `MARU_WORKBENCH_URL` | (없음) | 브라우저에서 OMV 웹 UI를 열 주소입니다([OMV 워크벤치 열기](#omv-워크벤치-열기)). 비워 두면 "OMV 워크벤치" 앱과 프로필 메뉴 항목이 보이지 않습니다. |
| `-helper-socket` | `MARU_HELPER_SOCKET` | (없음) | [권한 도우미](helper.md) 소켓의 절대 경로입니다(설치 스크립트는 `/run/maru-helper/helper.sock`). 비워 두면 도우미를 쓰는 기능이 꺼집니다. |
| `-terminal` | `MARU_TERMINAL` | `false` | [웹 터미널](terminal.md)을 허용합니다. 설정 앱의 "서버" 페이지에서도 켜고 끌 수 있습니다. |
| `-ssh-addr` | `MARU_SSH_ADDR` | `auto` | 웹 터미널이 접속할 SSH 서버 주소입니다. `auto`는 `/etc/ssh/sshd_config`의 `Port`로 `127.0.0.1`에 접속하므로 OMV에서 포트를 바꿔도 따라갑니다. 직접 적을 때는 루프백 `IP:포트`만 받습니다. |
| `-ssh-host-keys` | `MARU_SSH_HOST_KEYS` | `/etc/ssh/ssh_host_*_key.pub` | 웹 터미널이 받아들일 SSH 서버 호스트 공개 키 파일의 glob 패턴입니다. 보통은 바꾸지 않습니다. |
| `-public-origin` | `MARU_PUBLIC_ORIGIN` | (없음) | 브라우저가 대시보드에 접속하는 공개 HTTPS 주소입니다(`https://호스트[:포트]`, 경로 없이). [보안 강화 모드](security.md)의 패스키에 씁니다. 브라우저가 믿는 인증서의 도메인 이름이어야 하며 IP 주소는 받지 않습니다. 비워 두면 패스키를 쓸 수 없고 인증 앱(TOTP)과 복구 코드만 씁니다. |

## 상태 디렉터리와 백업

- 세션은 백엔드 메모리에만 있으므로 백엔드를 다시 시작하면 모든 사용자가 다시 로그인해야 합니다.
- `/var/lib/maru`에는 대시보드 자신의 상태만 들어 있으며 OMV 설정과는 관계가 없습니다. 백업할 때 이 디렉터리를 함께 복사하면 사용자 설정, 전역 설정, 올린 배경 이미지, 보안 강화 모드의 인증 수단이 유지됩니다.
- 인증 수단 기록에는 인증 앱의 비밀 키가 들어 있으므로 백업도 함께 보호해 주세요([설계와 한계](security.md#설계와-한계)).

## OMV 워크벤치 열기

`-workbench-url`을 설정하면 "모든 앱"·바탕화면 바로가기의 "OMV 워크벤치"와 프로필 메뉴의 "OMV 워크벤치 열기"가 OMV 웹 UI를 브라우저의 새 탭으로 엽니다.

- 값은 브라우저에서 OMV에 접속하는 주소입니다(예: `https://nas.example.lan/`). `http://`·`https://`로 시작하는 주소 또는 대시보드 기준 경로(`/`, `./`, `../`)를 받습니다. 대시보드를 OMV와 같은 호스트의 경로 접두사(예: `/desk/`) 아래에 두었다면 `/`도 됩니다. 쿼리·프래그먼트가 있거나 `nas.example.lan/`처럼 `http(s)://`가 없는 주소는 받지 않습니다.
- OMV 로그인은 그 탭에서 따로 합니다. OMV에는 비밀번호 없이 로그인을 넘겨받는 방법이 없어 대시보드 로그인을 OMV 탭에 넘길 수 없습니다. 이미 연 OMV 탭이 있으면 그 탭을 다시 쓰므로, 탭을 닫지 않는 동안에는 로그인이 유지됩니다. 처음 로그인하는 브라우저라면 OMV가 "새 브라우저 로그인" 알림 메일을 보낼 수 있습니다.
- OMV 웹 UI는 대시보드와 출처(호스트·포트)가 같을 때만 창(iframe)에 들어갈 수 있으므로, 대시보드 안 창이 아니라 브라우저 탭으로 엽니다.
