# 웹 터미널

"모든 앱"의 "터미널"은 대시보드에 로그인한 계정으로 이 NAS의 SSH 서버(sshd)에 접속한 셸을 창 안에 엽니다. 대시보드가 같은 호스트의 SSH 서버(`127.0.0.1`)에 SSH로 접속해 화면을 중계하므로, 누가 어떤 방법으로 들어갈 수 있는지는 OMV의 SSH 설정이 그대로 정합니다.

## 켜기

- 기본으로 꺼져 있습니다. 관리자가 설정 앱의 "서버" 페이지에서 "웹 터미널"을 켜거나 `MARU_TERMINAL=true`로 켭니다. 끄면 열려 있던 터미널도 바로 닫힙니다.
- OMV에서 SSH 서비스가 켜져 있어야 하고, 계정이 SSH 로그인을 허용한 그룹(OMV 기본값 `_ssh`)에 있어야 합니다. 그룹은 OMV 웹 UI의 사용자 편집 화면에서 더할 수 있습니다.
- OMV 기본 관리자 계정(`admin`)은 셸이 없어 쓸 수 없습니다. 다른 계정이나 root로 접속하는 기능은 없으며, root 작업은 셸 안에서 `sudo`로 합니다.
- 관리자는 [보안 강화 모드](security.md)로 웹 터미널 앞에 비밀번호 재확인이나 2차 인증을 둘 수 있습니다.

## 인증

- **권한 도우미가 있으면** 비밀번호를 다시 묻지 않습니다. 접속할 때마다 대시보드가 일회용 키를 만들고, [권한 도우미](helper.md)가 그 키를 `~/.ssh/authorized_keys`에 2분 동안 이 호스트 안의 접속에만 쓸 수 있는 줄(주석 `maru-ephemeral`)로 넣었다가 인증이 끝나면 바로 지웁니다. 공개 키만 받는 SSH 설정(OMV의 "Password authentication" 끔)에서도 됩니다.
- **도우미가 없거나 키를 쓸 수 없으면** SSH 서버가 묻는 비밀번호(와 2단계 인증 코드)를 터미널 안에서 입력합니다. 비밀번호는 저장하지 않고 SSH 서버로 바로 넘깁니다.
- 홈 디렉터리에 그룹이나 다른 사용자의 쓰기 권한이 있으면 SSH 서버가 그 안의 키를 무시하므로 일회용 키를 쓸 수 없습니다. 그 권한을 빼거나(`chmod go-w <홈 디렉터리>`) 비밀번호로 접속해 주세요.

도우미 없이 공개 키만 받는 SSH 서버를 쓴다면, 이 호스트 안의 접속에만 비밀번호를 허용할 수 있습니다. OMV 웹 UI의 SSH 설정 "추가 옵션"에 다음을 넣습니다. 추가 옵션은 `Include /etc/ssh/sshd_config.d/*.conf` 바로 앞에 들어가므로, 마지막 `Match all`이 없으면 그 뒤의 `Include`까지 이 조건 안에 들어갑니다.

```
Match Address 127.0.0.1,::1
    PasswordAuthentication yes
Match all
```

## 창과 세션

- 터미널 창은 여러 개 열 수 있습니다. "모든 앱"이나 바로가기의 터미널 아이콘을 누를 때마다 새 창이 열리고, 작업표시줄의 터미널 버튼을 우클릭(터치는 길게 누르기)해 "새 창"을 골라도 됩니다. 창마다 셸이 따로 열리고, 한 대시보드 세션에서 동시에 연 창은 다른 탭의 창을 합쳐 4개까지입니다.
- 한 대시보드 세션(로그인한 브라우저)은 SSH 연결 하나를 함께 쓰므로, 새 창이나 다른 탭에서 터미널을 열 때는 다시 묻지 않습니다.
- 창을 닫거나, 로그아웃하거나, 세션이 만료되면 셸이 끝납니다. 터미널에 입력하는 동안에는 세션이 연장되지만 출력만 나오는 동안에는 연장되지 않으므로, 오래 걸리는 작업은 `tmux`나 `screen` 안에서 실행해 주세요.
- 복사는 Ctrl+Shift+C, 붙여 넣기는 Ctrl+Shift+V입니다.

## 보안

- 대시보드는 SSH 서버의 클라이언트일 뿐입니다. SSH 서버는 원래 LAN에 열려 있으므로 대시보드가 뚫려도 새로 얻는 권한은 없고, 로그인 기록·PAM 세션·`AllowGroups` 같은 SSH 정책도 그대로 적용됩니다. 호스트 키는 `/etc/ssh/ssh_host_*_key.pub`와 비교해 같은 서버에만 접속합니다.
- 일회용 키는 도우미가 원래 할 수 있는 일(로그인한 사용자 자신의 홈에 쓰기) 안의 일이라 새 권한을 더하지 않습니다. 지우지 못한 줄도 2분 뒤에는 SSH 서버가 받지 않고, 다음 접속 때 지워집니다.
- SSH 서버와 fail2ban에는 접속지가 `127.0.0.1`로만 보입니다. 그래서 대시보드가 웹 터미널의 비밀번호 실패를 브라우저 IP·사용자 이름별로 따로 세어 잠급니다(로그인과 같은 기준). 대시보드 로그(`journalctl -u maru`)에는 사용자, 브라우저 IP, 결과만 남습니다.
