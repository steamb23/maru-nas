# 애드온 패키지

애드온 패키지는 마루 NAS 저장소 밖에서 만든 애드온입니다. 내장 앱처럼 "모든 앱"의 창과 바탕화면 위젯이 되고, 관리자가 설정 앱에서 파일(`.maru-addon`)을 올려 설치합니다. 대시보드를 다시 시작하지 않습니다.

패키지 화면은 대시보드와 분리된 샌드박스에서 돌고, 패키지가 미리 밝힌 OMV 읽기만 할 수 있습니다. 그래도 패키지 코드는 대시보드가 검사한 코드가 아닙니다. 권한을 검토하고 믿을 수 있는 작성자의 패키지만 설치하세요. 패키지를 만드는 방법은 [애드온 개발](addon-dev.md)에 있습니다.

## 설치하기

1. 설정 앱의 "애드온" 페이지(관리자)에서 "패키지 올리기…"를 누르고 `.maru-addon` 파일을 고릅니다.
2. 검토 화면에서 패키지 정보와 권한을 확인합니다. 아래 "검토 화면 읽기"를 보세요.
3. "설치"를 누르고 비밀번호를 다시 입력합니다. 보안 수단(패스키, 인증 앱)을 등록했으면 그 수단으로도 확인합니다.

- 설치하면 바로 모든 사용자의 "모든 앱"에 나타납니다(관리자 전용 패키지는 관리자에게만). 바로가기와 위젯은 사용자마다 따로 둡니다.
- 패키지 파일은 64MiB까지 올릴 수 있습니다. 리버스 프록시의 요청 본문 크기 제한도 그보다 커야 합니다([프록시 요구 사항](reverse-proxy.md#프록시-요구-사항)).
- 올린 파일은 검토하는 동안 30분까지 서버에 남고, 설치하지 않으면 지웁니다.
- 대시보드가 상태 디렉터리 없이 실행 중이면(개발 서버 등) 설치할 수 없습니다.
- 지금 버전은 백엔드(서버에서 도는 프로그램)가 없는 패키지만 설치합니다. 백엔드가 있는 패키지는 "이 대시보드는 아직 백엔드가 있는 패키지를 지원하지 않습니다"로 거절합니다.

## 검토 화면 읽기

검토 화면의 이름, 설명, 작성자는 패키지가 스스로 적은 값이며 확인되지 않았습니다. 패키지에는 서명이 없습니다. 작성자가 알려 준 SHA-256 값과 검토 화면의 SHA-256이 같은지 비교해 받은 파일이 맞는지 확인하세요.

| 항목 | 뜻 |
|---|---|
| 쓸 수 있는 사용자 | "모든 사용자" 또는 "관리자만". 관리자만이면 일반 사용자에게는 앱과 위젯이 보이지 않습니다 |
| 필요한 플러그인 | 이 패키지가 쓰는 OMV 플러그인. 설치되어 있지 않으면 앱이 "쓸 수 없음"으로 보입니다 |
| OMV 읽기 | 패키지가 읽을 수 있는 OMV RPC 메서드. 로그인한 사용자의 OMV 권한으로 부르므로 그 사용자가 OMV에서 볼 수 있는 값만 읽습니다 |
| OMV 쓰기 | 패키지가 바꿀 수 있는 OMV 설정. 있으면 위험 항목에 표시합니다 |
| 조작 | 패키지가 실행할 수 있는 동작(서비스 다시 시작 같은) |
| 백엔드 | 서버에서 도는 프로그램이 들어 있는지 |
| 백엔드 네트워크 | 백엔드가 연결할 수 있는 곳. "LAN"(이 네트워크의 다른 기기), "이 서버의 다른 서비스(루프백)" |

- 빨간 상자의 위험 항목은 꼭 읽어 주세요. OMV 쓰기 권한은 root에 준하는 신뢰가 필요합니다(OMV 관리자 권한으로 바꿀 수 있는 설정 중에는 root로 명령을 실행하게 되는 것이 있습니다).
- 같은 패키지의 새 버전을 올리면 "애드온 업데이트 검토"가 되고, 설치된 버전과 새 버전, 권한의 차이("새로 추가", "빠짐")를 보여 줍니다. 권한이 넓어지면 그렇다고 알려 줍니다.
- 경고: 작성자가 바뀐 경우, 설치된 버전보다 낮은 버전, 버전 번호는 같지만 내용이 다른 파일, 설치된 것과 같은 파일이면 검토 화면 위쪽에 알려 줍니다. 설치를 막지는 않습니다.

## 업데이트

- 같은 id의 패키지 파일을 올리면 업데이트합니다. 업데이트도 설치와 같은 확인을 거칩니다.
- 사용자가 열어 둔 패키지 창과 위젯은 대시보드가 다음에 앱 목록을 받을 때 새 버전으로 다시 뜹니다.
- 자동 업데이트는 없습니다. 대시보드를 업그레이드해도 설치한 패키지는 그대로입니다.

## 끄기, 켜기, 제거

- 설치한 애드온 목록의 스위치로 끄고 켭니다. 끄면 모든 사용자의 앱 목록과 바탕화면에서 빠지고, 열려 있던 창은 "쓸 수 없는 애드온"으로 바뀝니다.
- 다시 켤 때는 설치와 같은 확인(비밀번호)을 거칩니다. 끌 때는 묻지 않습니다.
- "제거"는 패키지 파일을 지웁니다. 백엔드가 있는 패키지는 백엔드가 저장한 데이터도 지울지 고릅니다(관리 확인이 필요합니다).
- 사용자의 바로가기와 위젯 배치는 끄거나 지워도 남아 있다가, 다시 켜거나 설치하면 돌아옵니다. 사용자가 패키지에 저장한 값은 다시 설치하면 보이지 않습니다(새로 설치한 패키지는 이전 데이터를 읽지 못합니다).
- 개발 서버가 불러온 개발 패키지("개발" 배지)는 여기서 끄거나 지울 수 없습니다([애드온 개발](addon-dev.md)).

## 쓸 수 없는 패키지

목록에서 "잘못됨", "호환 안 됨", "충돌", "허용 안 됨" 배지가 붙은 패키지는 켜져 있어도 쓰지 않습니다. "자세히"에서 이유를 봅니다.

- 호환 안 됨: 이 대시보드 버전보다 새 SDK가 필요합니다. 대시보드를 업데이트하거나 이 버전에 맞는 패키지를 쓰세요.
- 충돌: 내장 애드온이나 먼저 설치한 다른 패키지와 id가 같습니다. 대시보드를 업그레이드하며 같은 id의 내장 애드온이 생기면 내장 애드온을 씁니다.
- 허용 안 됨: 애드온 패키지에 허용하지 않는 OMV 메서드(명령 실행, 자격 증명 읽기 등)를 선언했거나, 대시보드가 예약한 id를 씁니다.
- 잘못됨: 설치한 파일을 읽을 수 없습니다. 패키지를 다시 설치하세요.
- 설치 기록 파일을 읽지 못하면 페이지 위쪽에 알리고 설치한 패키지를 모두 쓰지 않습니다. 서버 로그를 확인하세요.

## 사용자에게 보이는 모습

- 패키지 창의 제목 표시줄에는 "애드온 패키지" 배지가 붙습니다. 패키지는 이름을 스스로 정하므로 내장 앱과 이름이 같을 수 있습니다.
- 패키지가 요청한 확인 대화상자는 "<이름> 애드온의 요청", 알림은 "애드온 <이름>" 제목으로 보입니다.
- 대시보드는 패키지 창 안에서 비밀번호나 보안 수단을 묻지 않습니다. 패키지 창 안에 비밀번호 입력 칸이 보이면 입력하지 마세요.
- 패키지가 사용자마다 저장하는 값은 패키지마다 64KiB, 사용자마다 1MiB까지입니다.

## 백업

설치한 패키지와 사용자가 패키지에 저장한 값은 대시보드의 상태 디렉터리(`/var/lib/maru`)에 있습니다. [상태 디렉터리와 백업](configuration.md#상태-디렉터리와-백업)처럼 이 디렉터리를 백업하면 함께 백업됩니다.

## 위험과 한계

- 패키지 화면은 대시보드의 쿠키, 저장소, 다른 앱의 화면에 닿지 못하고 직접 네트워크 요청을 보내지 못합니다. 다만 브라우저의 일부 기능(WebRTC, DNS 미리 가져오기)까지 완전히 막지는 못하므로, 패키지 화면에 보인 값은 작성자에게도 전해질 수 있다고 보세요.
- 패키지가 읽을 수 있는 OMV 값은 검토 화면의 "OMV 읽기"로 제한되지만, 그 메서드가 돌려주는 값은 모두 읽습니다.
- 패키지 창 안에 그린 가짜 입력 화면은 대시보드가 막을 수 없습니다.
- 서명, 카탈로그, 자동 업데이트가 없습니다. 파일을 받은 곳과 SHA-256으로 확인하세요.
