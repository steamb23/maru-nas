# 시스템 업데이트

"모든 앱"의 "시스템 업데이트"는 OMV와 Debian 패키지의 업데이트를 보여 주고, 업데이트를 확인하고, 모두 설치합니다. OMV 워크벤치의 "업데이트 관리 › 업데이트"와 같은 일을 하며 관리자만 씁니다.

## 업데이트 목록

- 목록은 OMV가 만들어 두는 업데이트 목록을 그대로 보여 줍니다. OMV는 매일 한 번, 그리고 업데이트를 확인하거나 설치할 때마다 목록을 다시 만듭니다. "마지막 확인"은 OMV가 목록을 마지막으로 만든 시각입니다.
- "업데이트 확인"은 저장소에서 패키지 목록을 다시 받습니다(`apt-get update`). 보통 10초에서 1분쯤 걸립니다.
- 패키지마다의 변경 기록과 업데이트 설정(사전 릴리스 업데이트, 자동 업데이트 등)은 OMV 워크벤치에서 봅니다. 창의 링크는 [OMV 워크벤치 주소](configuration.md#omv-워크벤치-열기)를 설정했을 때만 보입니다.
- 관리자에게는 업데이트가 있으면 알림 센터에 "업데이트가 있습니다" 알림이 보입니다.

## 모두 설치

- 받을 수 있는 업데이트를 모두 설치합니다(`apt-get dist-upgrade`, OMV 워크벤치의 "업데이트 설치"와 같습니다). 패키지를 골라 설치할 수는 없습니다.
- 설치하는 동안 서비스가 다시 시작되어 SMB/CIFS·NFS 공유, Docker 컨테이너, OMV 워크벤치가 잠시 끊길 수 있습니다. 사용이 적은 시간에 설치하세요.
- 다른 패키지 작업(자동 보안 업데이트 등)이 apt·dpkg를 쓰고 있으면 시작하지 않습니다. 잠시 뒤 다시 시도하세요.
- OMV에 적용하지 않은 apt 설정 변경이 있으면 업데이트 확인을 시작하지 않습니다. OMV 워크벤치에서 변경 사항을 먼저 적용하세요.
- OMV 8.5.10부터는 설치가 openmediavault 패키지를 지우게 되면 OMV가 설치를 멈춥니다. 이때는 OMV 워크벤치에서 저장소 설정을 확인하세요.
- 확인과 설치는 한 번에 하나만 진행됩니다. 다른 관리자가 시작한 작업이 진행 중이면 그 작업이 끝난 뒤에 시작할 수 있습니다.

## 작업 진행과 결과

- 확인과 설치는 서버에서 진행됩니다. 창을 닫거나 로그아웃해도 계속 진행되며, 대시보드가 작업을 끝까지 지켜본 뒤 시작한 관리자에게 결과를 알립니다.
- "작업" 탭에서 진행 중인 작업의 출력(apt가 내는 내용)을 실시간으로 봅니다. 탭은 가장 최근 작업을 보이고, 끝난 작업은 결과 알림의 "출력 보기"로 다시 엽니다.
- 작업이 진행 중이고 창이 열려 있으면 세션이 만료되지 않습니다.
- 창이 닫혀 있으면 알림 센터 맨 위의 "백그라운드 작업"에 진행 중인 작업이 보입니다.
- 결과 알림(성공, 실패, 결과를 알 수 없음)은 작업을 시작한 관리자에게만 보이고, 확인한 뒤 지울 수 있습니다. 로그아웃한 동안 끝난 작업은 다음 로그인 때 알림으로 뜹니다. 결과는 사용자마다 최근 10개를 30일 동안 둡니다.
- 커널처럼 다시 시작이 필요한 패키지를 설치하면 "다시 시작해야 합니다" 알림이 뜹니다. 알림이나 창의 "다시 시작…"으로 전원 대화상자를 엽니다.

## 한계

- 관리자가 아무도 로그인하지 않은 동안은 대시보드가 출력을 받지 못합니다("감시 대기"). 작업은 서버에서 계속 진행되고, 관리자가 다시 로그인하면 이어서 받습니다. 그 사이 NAS가 다시 시작되면 결과는 "알 수 없음"입니다. 실제 상태는 업데이트 목록과 "다시 시작해야 합니다" 알림으로 확인하세요.
- OMV 워크벤치의 알림 패널에서 같은 작업을 열어 끝까지 보면 대시보드가 결과를 읽지 못해 결과가 "알 수 없음"이 되거나 출력 일부가 빠질 수 있습니다. 워크벤치에서 작업을 멈춘 경우도 같습니다.
- 작업이 실패하면 마지막 1초 안팎의 출력이 보이지 않을 수 있습니다. OMV가 실패한 작업의 남은 출력을 주지 않기 때문입니다.
- 출력이 아주 길면 작업마다 끝부분 2~4MiB만 남기고 앞부분은 버립니다.
- openmediavault 패키지를 업그레이드하는 동안 OMV의 세션이 끊기면 대시보드도 로그아웃될 수 있습니다. 다시 로그인하면 작업을 이어서 봅니다.
