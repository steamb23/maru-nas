# 묶기와 배포

패키지 파일(`.maru-addon`)은 패키지 디렉터리를 gzip으로 압축한 tar입니다. SDK의 `maru-addon` CLI가 검사하고 묶습니다.

## 파일 구성

```
my-addon/
├── manifest.json        필수
├── icon.svg             필수(SVG)
├── i18n/
│   ├── en.json          필수
│   └── ko.json
├── ui/                  보기의 HTML과 자산(하위 폴더 가능)
│   ├── window.html
│   ├── window.js
│   └── assets/…
├── backend/             백엔드 실행 파일(manifest가 백엔드를 선언했을 때)
│   ├── linux-amd64
│   └── linux-arm64
├── LICENSE              선택
└── README.md            선택
```

- 최상위에는 위 이름만 둘 수 있습니다. 개발 디렉터리의 `dev/`는 개발용 파일을 두는 곳이라 묶지 않습니다.
- 경로의 각 조각은 영문자나 숫자로 시작하고 영문자·숫자·`.`·`_`·`-`로 된 100자 이하입니다. 숨김 파일(`.`으로 시작), 공백, 한글 같은 이름은 받지 않습니다. 깊이는 16단계까지입니다.
- 일반 파일과 디렉터리만 받습니다(심볼릭 링크 등은 받지 않습니다). 권한은 받은 값과 상관없이 설치할 때 정해집니다.
- `i18n/`에는 대시보드가 지원하는 언어의 파일(`<언어>.json`)만 둡니다. `i18n/`과 `backend/`에는 하위 폴더를 둘 수 없습니다.
- `backend/`에는 백엔드 실행 파일 `linux-amd64`, `linux-arm64`(정적으로 빌드한 64비트 리눅스 ELF 실행 파일)를 둡니다. 백엔드를 선언한 패키지는 서버 아키텍처의 실행 파일이 있어야 설치되므로 둘 다 넣으세요. manifest에 `backend` 선언 없이 백엔드 파일이 있으면 받지 않습니다([애드온 백엔드](addon-backend.md#제약)).

## 한도

| 대상 | 한도 |
|---|---|
| 패키지 파일 | 64MiB |
| 풀린 파일 합 | 160MiB |
| 항목 수 | 2000개 |
| `ui/` 파일 하나 | 8MiB |
| 백엔드 실행 파일 하나 | 64MiB |
| `manifest.json` | 64KiB |
| 번역 파일 하나, `icon.svg` | 128KiB |
| `LICENSE`, `README.md` | 256KiB |

## maru-addon

SDK가 npm에 공개되기 전에는 마루 NAS 저장소 체크아웃에서 `node sdk/js/cli/maru-addon.mjs`로 실행합니다. Node.js 20.19 이상이 필요하고 다른 의존성은 없습니다.

| 명령 | 내용 |
|---|---|
| `init <디렉터리> [--id <id>] [--ts] [--backend]` | 새 패키지를 만듭니다. id는 디렉터리 이름에서 정하고, `--ts`면 TypeScript + Vite 프로젝트, `--backend`면 패키지 디렉터리(`addon/`) 옆에 Go 백엔드 모듈을 더합니다 |
| `validate <디렉터리 또는 파일>` | 패키지 디렉터리나 `.maru-addon` 파일을 검사합니다. 디렉터리에 백엔드 실행 파일이 없으면 알림만 보입니다 |
| `pack <디렉터리> [-o <파일>]` | 검사한 뒤 묶습니다. 기본 이름은 `<id>-<version>.maru-addon`이고 SHA-256과 판 이름(rev)을 보여 줍니다. 백엔드를 선언했는데 실행 파일이 없으면 묶지 않습니다 |

- CLI는 manifest의 구조와 파일 구성을 대시보드와 같은 규칙으로 봅니다. 필드 사이의 조건과 문구의 제어 문자, 허용하지 않는 메서드, 다른 애드온과의 충돌은 대시보드가 설치할 때 봅니다. 묶기 전에 개발 서버에서 한 번 불러 보세요(설정 앱의 "애드온" 페이지에 이유가 보입니다).
- `pack`은 같은 파일이면 같은 tar를 만듭니다(경로 순서, 수정 시각과 소유자 0, 정해진 권한). gzip 압축 결과는 기기의 zlib 버전에 따라 다를 수 있어 SHA-256은 기기마다 다를 수 있습니다. 배포할 파일을 한 번 만들고 그 SHA-256을 함께 알리세요.

## 버전과 업데이트

- 새 판을 낼 때 `version`을 올립니다. 관리자가 같은 id의 파일을 올리면 업데이트가 됩니다.
- id는 바꾸지 마세요. id가 다르면 다른 패키지로 설치되고, 사용자의 바로가기·위젯·저장값이 이어지지 않습니다.
- `author.name`을 바꾸면 검토 화면에 "작성자가 다릅니다" 경고가 뜹니다. 낮은 버전, 같은 버전 번호의 다른 파일도 경고가 뜹니다.
- 권한(OMV 메서드, 관리자 전용 여부 등)을 넓히면 검토 화면이 "새로 추가"로 표시합니다. 변경 기록에도 적어 주세요.
- 위젯 크기 범위를 줄이면 사용자가 둔 위젯은 새 범위에 맞춰집니다.
- `sdk` 수준을 올리면 그보다 낮은 대시보드에는 설치되지 않습니다. 필요한 기능이 생겼을 때만 올리세요.

## 배포

- 파일을 내려받을 수 있는 곳(GitHub 릴리스 등)에 `.maru-addon`과 SHA-256을 함께 올리세요. 대시보드에는 패키지 카탈로그·서명·자동 업데이트가 없습니다.
- README에 패키지가 읽는 OMV 메서드와 그 이유, 필요한 플러그인, 지원하는 OMV 버전을 적어 주세요. 관리자가 검토 화면과 비교합니다.
- 백엔드가 있는 패키지면 백엔드가 하는 일, 조작이 바꾸는 OMV 설정, `lan`·`loopback`을 요청한다면 그 이유, 데이터 디렉터리에 두는 내용도 적어 주세요. 설치한 대시보드는 이후 버전부터 백엔드를 실행한다는 점도 알려 주세요.
- 라이선스는 자유입니다. SDK(MIT)에서 복사한 코드가 있으면 그 고지를 남기세요.
