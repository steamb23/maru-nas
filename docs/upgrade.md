# 업그레이드

## SSH로 업그레이드

저장소에서 실행합니다.

```sh
git pull
./install.sh
```

`stable`을 받았다면 `git pull`로 최신 릴리스가 내려옵니다. 태그를 체크아웃해 특정 버전을 쓰고 있다면 `git pull` 대신 `git fetch --tags`로 받고 새 버전의 태그를 체크아웃합니다.

이미 설치되어 있으면 `./install.sh`는 설치된 설정을 그대로 써서 빌드하고 설치합니다. 요약을 보여 준 뒤 "업그레이드", "설정 바꾸기", "취소" 중에서 고르게 하며, "설정 바꾸기"는 `--reinstall`처럼 지금 값을 기본값으로 모든 설정을 다시 묻습니다. 일반 사용자라면 sudo 비밀번호만 입력하면 됩니다. 대시보드와 권한 도우미가 다시 시작하므로 모든 사용자가 다시 로그인합니다.

- 새 버전에서 생긴 설정만 묻습니다. 예를 들어 보안 강화 모드가 생기기 전 버전에서 올라오면 패스키에 쓸 공개 주소를 묻습니다.
- 설정 옵션(`--listen` 등)을 함께 주면 그 항목만 기존 값 대신 씁니다.
- 기존 값이 새 버전의 검사를 통과하지 못하면 경고하고 그 설정만 다시 묻습니다(기존 값이 아닌 기본값을 보여 줍니다).
- 스크립트에서는 `./install.sh --upgrade`를 씁니다. 확인 없이 업그레이드하고, 설치되어 있지 않으면 실패합니다.
- 표준 입력이 터미널이 아니면 고르지 않고 업그레이드합니다. 물어야 할 설정이 있으면 그 옵션 목록을 알리고 멈추므로, 옵션으로 주거나 `--reinstall`로 다시 실행합니다.

## 대시보드에서 업그레이드

SSH로 `git pull`과 `./install.sh`를 실행하는 대신, 관리자가 설정 앱의 "업데이트" 페이지에서 업그레이드합니다. 설치에 쓴 로컬 git 저장소에서 새 버전을 찾고, 저장소 소유자 계정으로 빌드한 뒤 root로 설치합니다.

### 켜기

- 권한 도우미를 설치할 때 `--web-upgrade`로 허용하고 `--no-web-upgrade`로 끕니다. 새로 설치할 때 질문의 기본값은 허용입니다.
- 이 설정이 없던 버전에서 업그레이드하면 꺼진 채로 둡니다. 켜려면 `./install.sh --web-upgrade`나 `./install.sh --reinstall`을 실행합니다.
- 저장소를 일반 사용자 계정으로 클론해야 합니다. 저장소 소유자가 root이면 허용할 수 없습니다.
- git과 빌드는 저장소 소유자 계정으로 실행하므로 그 계정에서 git·Go·Node.js·npm·make를 쓸 수 있어야 합니다. 설치 스크립트를 일반 사용자로 실행할 때마다 이 도구를 찾은 디렉터리를 빌드 PATH로 기록하므로, 도구를 옮겼다면 저장소 소유자 계정으로 `./install.sh`를 다시 실행합니다.
- `MARU_STATE_DIR`로 상태 디렉터리를 `/var/lib/maru` 밖으로 옮긴 설치에서는 업데이트 페이지가 꺼져 있습니다.

### 확인과 업그레이드

1. 업데이트 페이지에서 확인을 누르면 새 버전, 그 사이의 커밋 목록, 새 버전이 묻는 설정, 업그레이드한 뒤 할 일을 보여 줍니다. 확인 방법은 두 가지입니다.
    - **원격에서 가져와 확인**: 저장소 소유자 계정으로 `git fetch`를 하고 지금 브랜치의 추적 브랜치(예: `origin/stable`)를 대상으로 삼습니다. 지금 체크아웃에서 그 브랜치로 fast-forward할 수 있어야 합니다. 그 계정의 git 설정과 자격 증명을 그대로 쓰고 비밀번호나 SSH 호스트 키 확인을 묻지 않으므로, 그 계정에서 묻는 것 없이 `git fetch`가 되어야 합니다.
    - **로컬 저장소만 확인**: SSH로 받아 둔 지금 체크아웃(HEAD)을 대상으로 삼습니다. 태그를 체크아웃한 설치나 로컬 커밋도 쓸 수 있습니다.
    - 두 방법 모두 작업 트리에 커밋하지 않은 변경이 없어야 하고, 대상이 설치된 커밋에서 이어져야 합니다.
2. 물은 설정에 답하고 "업그레이드"를 누르면 비밀번호로 root 권한 상승을 한 뒤 진행 단계를 보여 줍니다.
3. 설치 단계에서 maru와 권한 도우미가 다시 시작하므로 "마루 NAS를 다시 시작하는 중" 화면으로 바뀝니다. 마루 NAS가 돌아오면 페이지를 새로 고치고, 다시 로그인하면 업데이트 페이지가 결과를 보여 줍니다.

빌드가 오래 걸려 그동안 대시보드를 조작하지 않으면 OMV 세션이 끝나 로그인 화면으로 먼저 돌아갈 수 있습니다. 업그레이드는 그대로 진행되며, 다시 로그인하면 업데이트 페이지가 진행 상황을 이어서 보여 줍니다. 서비스 로그는 `journalctl -u maru-upgrade`에 있습니다.

### SSH로 올려야 할 때

웹으로 넘을 수 없는 변경이면 업그레이드 대신 이유와 SSH로 실행할 명령을 보여 줍니다. 설치 기록이 없을 때, 로컬 커밋 때문에 fast-forward할 수 없을 때, 새 버전이 웹에서 물을 수 없는 설정을 추가했을 때, 필요한 Go·Node.js 버전이 더 높을 때 등입니다.

저장소 소유자 계정으로 SSH 접속해 저장소에서 `./install.sh`(또는 `./install.sh --reinstall`)를 실행합니다. 한 번 수동으로 올리면 그다음 버전부터 다시 대시보드에서 업그레이드할 수 있습니다.

### 실패했을 때

- 빌드 전이나 빌드 중에 실패하면 설치된 것은 바뀌지 않습니다. 다만 원격에서 가져와 진행했다면 작업 트리는 fast-forward된 채로 남을 수 있습니다.
- 설치 단계에서 실패하면 대시보드가 뜨지 않을 수 있습니다. SSH로 저장소에서 `./install.sh`를 다시 실행해 복구합니다. 자동으로 이전 버전으로 되돌리지 않습니다.

### 보안과 주의

- 이 기능을 켜면 root 권한 상승한 세션으로 할 수 있는 일이 "설치된 저장소로 업그레이드"까지 넓어집니다. 업그레이드는 저장소에서 빌드한 코드를 root로 실행하므로, 저장소를 바꿀 수 있는 계정(저장소 소유자)은 SSH로 `./install.sh`를 실행할 때와 마찬가지로 업그레이드를 통해 root로 코드를 실행할 수 있습니다. 저장소 소유자 계정은 관리자 계정처럼 다루고, 업그레이드하기 전에 확인 화면의 커밋 목록을 봐 주세요.
- 확인에는 권한 상승이 필요 없으므로 대시보드가 뚫리면 확인을 계속 요청할 수 있습니다. 그때 하는 일은 저장소 소유자 계정의 `git fetch`와 임시 빌드뿐입니다.
- 이 기능이 필요 없다면 `--no-web-upgrade`로 꺼 둡니다.
- 대시보드에서 업그레이드하는 동안에는 SSH로 `./install.sh`를 실행하지 마세요. 서로 막지 않습니다.
- 아이콘 서브모듈 커밋이 바뀐 버전은 서브모듈 원격(GitHub)에서 그 커밋을 받을 수 있어야 합니다.
